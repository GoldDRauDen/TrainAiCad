# Luan App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A LAN web app on the Admin's Windows machine that queues TrainAiCad E2E/QA jobs, runs each as a headless `claude -p` session in its own git worktree, and shows progress, history and a "Chờ duyệt" inbox.

**Architecture:** FastAPI + SQLite (WAL) in one `pythonw` process with a tray icon. A scheduler thread hands queued runs to N slot worktrees; one worker thread per run does prepare → `claude -p` (stream-json) → archive → final status. A static HTML/CSS/JS front end polls `/api/board` with ETag.

**Tech Stack:** Python 3.11+ (local 3.12), FastAPI 0.141, uvicorn 0.52, sqlite3 (FTS5), pystray + Pillow (tray), openpyxl via `tools/slip.py`, vanilla JS, Be Vietnam Pro + JetBrains Mono (vendored woff2).

**Spec:** `docs/superpowers/specs/2026-10-30-luan-app-design.md` (+ mockup `2026-10-30-luan-app-mockup.html`)

## Global Constraints

- All app code under `luan_app/`; app deps in `luan_app/requirements.txt` (`fastapi`, `uvicorn`, `pystray`, `pillow`, `httpx` for tests); repo `requirements.txt` unchanged.
- Data dir default `%LOCALAPPDATA%\LuanApp` (env `LUAN_DATA_DIR`); slots root default `C:\TrainAiCad-slots` (env `LUAN_SLOTS_ROOT`); port 8765, bind `0.0.0.0`.
- Defaults: slots 3 (range 1–6), timeout 120 min, usage-limit pause 30 min when no reset time is given, board cache 1 s, client poll 2 s (10 s hidden tab), admin session 12 h, lockout 5 failures → 5 min per IP, user cookie 1 year.
- Run statuses: `QUEUED PREPARING RUNNING FINISHING DONE REVIEW ERROR CANCELLED`; active = first four.
- Users never send free text to Claude: only a validated path + codes from the slip, inserted into the fixed prompt; subprocess args as a list, never a shell string.
- The app never writes into `C:\TrainAiCad` (the Admin's checkout) while running jobs; jobs run only in slot worktrees.
- UI copy in Vietnamese with diacritics; tokens/colors/fonts exactly as the approved mockup.
- Tests never call real Claude; they use `luan_app/tests/fake_claude.py`. Tests must pass on ubuntu (CI) and Windows; Windows-only code paths behind `sys.platform == "win32"`.

## Review Focus

1. A job path with trailing `\`, different case, `/` separators or surrounding quotes/spaces must be treated as the same job (dedupe) — tests in Task 2 and Task 8.
2. A job folder without `*_依頼.xlsx`, or with two of them, must still be runnable as "all codes" with a warning, not crash — Task 2.
3. The Claude process hangs or prints non-JSON lines / partial lines — runner must not crash and the timeout must still kill it — Task 6.
4. Two browsers submit the same path at the same instant — only one run is created (transaction) — Task 8.
5. App restarts while a run is RUNNING and its `claude` child is still alive — recovery must kill the orphan tree, mark ERROR, free the slot — Task 8.

### Task 8: Scheduler (queue, slots, lifecycle, cancel, recovery, pause)

**Files:**
- Create: `luan_app/scheduler.py`, `luan_app/tests/test_scheduler.py`

**Interfaces:**
- Consumes: Store (T1), sources (T2), prompts/progress (T4), Slots (T5), runner (T6), archive (T7).
- Produces: `class Scheduler(store, paths, slots, clock=time.time, exe_override=None)`:
  - `submit(user: dict, kind: str, path: str, codes: list[str]|None, confirm_rerun: bool, is_admin: bool) -> int`: re-runs `sources.inspect` + `validate_codes`; QA requires `is_admin` (`PermissionError`); `NeedConfirm(last_run)` when a final run exists for the key and not `confirm_rerun`; `Duplicate` from the store passes through.
  - `cancel(run_id, by_user: dict, is_admin: bool)`: owner or admin else `PermissionError`; QUEUED → CANCELLED directly; active → set cancel event, `ClaudeProcess.kill()`; the worker finishes as CANCELLED and records `cancelled_by`.
  - `rerun(run_id, user, is_admin) -> int`: same path/kind/codes, `rerun_of=run_id`, `confirm_rerun=True`.
  - `tick()`: if `queue_paused_until` in the future → do nothing; free slots = `settings.slots` − slots in use; for each free slot pop oldest QUEUED and start `threading.Thread(target=self._work, args=(run, k), daemon=True)`. Slot numbers are 1..slots; a slot is "in use" while its worker thread is alive.
  - `_work(run, k)`: PREPARING (`slots.ensure/prepare`, store commit) → RUNNING (`ClaudeProcess.start` with `build_prompt`, env `LUAN_RUN_DIR`, `PYTHONUTF8=1`; loop `wait(1)` updating `store.update_run(activity=..., activity_at=..., codes_status_json=code_rows(...))` every 2 s; enforce `timeout_min`) → FINISHING (archive, `final_status`, review items with `run_id`, `touched()` → `repo_touched` + `reset`, `index_run`, notify the owner `kind=status` with text like `"521030-10 xong: 4/4 PASS"`) → final. Any exception → ERROR with message; slot always released (`finally`).
  - Usage limit (`proc.usage_limit` or result text) → run ERROR `"Hết hạn mức Claude"` and `set_settings(queue_paused_until=<reset time or now+30 min ISO>)`.
  - `resume_queue()`: clears `queue_paused_until`.
  - `recover_on_start()`: for every ACTIVE non-QUEUED run: if `pid` alive → kill tree; set ERROR `"Bị ngắt do app khởi động lại"`; `slots.reset(slot)` best effort.
  - `start()` / `stop()`: background loop calling `tick()` every 1 s; `stop()` kills all running processes (used by tray "Thoát").
  - `running_snapshot() -> dict[int, dict]` (run_id → {activity, activity_at, slot}) for the board.
