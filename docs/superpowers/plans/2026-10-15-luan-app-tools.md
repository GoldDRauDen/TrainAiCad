# LuanAppTools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a working Windows-local review application that discovers LAN drawing jobs, automatically operates Claude, exports canonical DXFs, and presents auditable progress and outputs.

**Architecture:** Add an optional `LuanAppTools` Python package and built React frontend beside existing rules/tools. SQLite and local immutable workspaces coordinate source versions, bounded solver attempts and output publication. Official Claude Code remains the subscription client; the application owns deterministic CAD tools and optional manually activated 9Router calls.

**Tech Stack:** Python 3.11+, FastAPI, uvicorn, SQLite, PyMuPDF, ezdxf, PyYAML; React/TypeScript/Vite; pytest and browser smoke tests.

**Spec:** `docs/superpowers/specs/2026-10-15-luan-app-tools-design.md` (approved by user).

## Global Constraints

- One Windows machine and one AI account; source/output folders can be UNC LAN shares. UI binds loopback.
- Every output is for human review, never an automatic manufacturing approval.
- One job is one folder. Combined DXF goes into that folder. Optional individual DXFs contain PASS parts only and have a separate output link.
- At most three active jobs, at most three AI calls globally; default two AI calls; at most one Opus call concurrently.
- Two solver attempts TOTAL per code/run; QA cannot secretly repair as a third attempt. Pause/reconnect do not reset budgets.
- Claude first: Haiku 5.5 medium, Sonnet 5.5 high/xhigh/max, automatic exceptional Opus 5.5. 9Router is manual opt-in; GPT is unavailable by default, not a pretend working integration.
- Tracked source changes requeue the latest stable source; output writes never trigger a new input version. Obsolete runs cannot publish.
- Pin source hashes and repo commit. Keep existing engineering authority, mandatory routing and canonical export/read-back. Do not modify engineering rules/formulas.
- Never fabricate PASS, geometry, quota or real-account test evidence. Preserve partial proved results and repository review fallbacks.
- Keep reusable app dependencies separate from root requirements. Do not put runtime data, credentials, node_modules or screenshots in git.
- Existing baseline: `dee7486`; `python3 -m pytest -q` reports 286 passed. Work branch: `codex/luan-app-tools-20261015`.

`LuanAppTools/core/` owns settings, SQLite, source snapshots and publication. `LuanAppTools/ai/` owns provider protocol/processes, routing and bounded deterministic tool requests. `LuanAppTools/cad/` owns pinned repository access, source evidence, canonical execution and previews. `LuanAppTools/service/` owns orchestration and HTTP routes. `LuanAppTools/frontend/` owns the React UI. Startup scripts and app requirements live at `LuanAppTools/`.

Task 1 exports `Settings`, `Store`, source discovery/snapshot helpers and `Publisher`; Task 2 exports asynchronous runner and CAD/pipeline primitives; Task 3 integrates them into `ApplicationService` and `create_app`; Task 4 consumes the published HTTP contract; Task 5 validates complete interactions and Windows distribution. Actual signatures established in each task must be documented in its report before the next task starts.
