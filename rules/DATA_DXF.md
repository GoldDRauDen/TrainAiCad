# DATA_DXF — customer DXF DATA (source class PDF_DATA_RAW; also any DXF used as evidence)

DATA = physical geometry and provenance. PDF = code, material, t, view/face meaning, witnesses, scale, revisions, Nobi, manufacturing semantics. Never redraw or retype DATA from PDF numbers, bbox or screenshots.

## 1. Decode, pick, assemble (tools do the numbers)
1. `python tools/dxf_digest.py data.dxf --out digest.json --png v.png`: every primitive decoded (bulge from the START vertex, closed last→first, INSERT transforms, ELLIPSE/SPLINE listed UNKNOWN, never flattened) with an id and one home (view / `B_*` bucket). Customer DATA is a whole sheet (frame, title block, views, iso, exploded text; KH646 = CATIA sheet). Layer/colour/linetype are hints only.
2. You classify: which view is the part, which pieces are `PHYSICAL_CUT_OR_FACE_EDGE`, holes/slots/features, bend support, thickness lines (prove faces, never CUT), hidden/projection, dimension/construction, duplicates. Prove scale/rotation/mirror per view from the PDF (a 1:2 view → ×2).
3. `python tools/dxf_assemble.py digest.json plan.json --out assembled.json`: copies the numbers, changes only layer/colour/linetype + your proved rigid transform, needs a reason for every excluded piece and re-checks it against the source both ways.
4. Flat part: a spec part with `data: assembled.json` + `members:` (the PDF meaning of each member: `ev`, `group`/`qty`, `thread`, `pdf_d`, `piercing`) → `tools/run_job.py` (`tools/BUILD_CANONICAL_SPEC.md` §DATA). The tool adds Laser R on sharp DATA corners, tap pilots, POINT/CIRCLE, the DATA/PDF gate and the `manufacturing_change_ledger`.
5. Bent part (KH646 CATIA sheets): faces/ODs/Nobi in a `bend:` block (job `customer_code: 646` → KH646 Nobi table), `outline` as usual, and the DATA view as `data:` + `data_faces:` (assemble it at the proved scale, along axis running with the chain, flat edge at y = 0): per face shown flat in that view, `at` = the view coordinate of its datum (`from: start` = previous face's outer plane or the first free edge; `from: end` = next face's outer plane or the last free edge) and `to` = the other end of its part of the view. Ears and web seen in one plan view are two entries. The tool puts each feature on its face, gates middle-face spans against the OD. Read every face's OD from the profile first: a flat that matches the slip size proves nothing (a 2-bend U and the 4-bend eared U differ by 0.04). Several DATA views of one bent part: `data_views` — one assembled file per view with its own proved mirror/rotation, `origin` and `data_faces`; the edges the views are read from are `datum` members (`dxf_assemble`) and every face range and outline corner is such a reference (`LEFT.min.x`, `START`/`END`), never a typed number (`tools/BUILD_CANONICAL_SPEC.md`). A dashed circle is a hole of the opposite face only when a PDF note scopes it (`4-Ø7 反対側`). Face ODs and the width are DATA spans (`od: {span: [ref, ref], pdf: n}`), corner R/C are the DATA arc/chamfer (`R: RC.radius, pdf_R: 5`; a drawn chamfer with no callout stays drawn + FLAG), a piece judged by no plan is found by `tools/dxf_closure.py`, and the build maps every harvested coordinate back to DATA (`DATA_ROUNDTRIP_FAIL`); views that disagree by <= 0.02 mm are closed keeping the edge nearer to the PDF dimension (`CLOSURE_SNAP` row). Two-axis DATA parts: by hand.

## 2. Same parameter, then change
- Compare a PDF value with DATA only for the same physical parameter (code, group, face, both witnesses, inside/outside). General `Δ < 0.1` keeps DATA, `Δ ≥ 0.1` → `DATA_PDF_DIM_DIFF` (exactly 0.1 flags); the threshold and `data_pdf_policy` per customer are in `data/customers.yaml` and applied by the tool (`pdf_d`, `envelope`). A pass never snaps DATA to the PDF nominal. No policy waives hole count/type/M/Ø/position, topology, revisions or read-back.
- Allowed changes only by a routed rule with proved scope (mid-tolerance, M pilot, explicit R/C, Laser R, Nobi placement), each a ledger row: member, old, new, rule, gate.
- Taps: the concentric nominal ring is excluded as `TAP_NOMINAL_RING`; one pilot per tap (`HOLE_TAP.md` §1). Ring role ambiguous → FLAG, never choose by size.

## 3. Invariance and completeness
- Outside the changed scopes the result is physically identical to DATA after canonical AND saved-DXF read-back (`dxf_assemble` checks both directions; the 0.1 threshold is not a redraw tolerance). LINE/ARC vs exact bulged polyline is equivalent; entity counts and OVERKILL prove nothing.
- Every active physical source curve/family is in canonical (or excluded with a reason), every output maps to DATA or a ledger row.
- VIEWS_ONLY only after every DATA view/face/primitive was harvested and every face-graph candidate tried.
- DATA is copied 100%: never add, merge, split or patch a piece or the digest. Noise ≤1e-3 mm, T-junctions, origin shift, J/LJ turn: tools, ledger rows. ELLIPSE/SPLINE in a contour → FLAG, never an arc. Milled-recess outlines (`2mm削る`) are not cuts.
- Reference/audit only: normalise exact duplicate entities for counting, report `REFERENCE_ANOMALY`.
