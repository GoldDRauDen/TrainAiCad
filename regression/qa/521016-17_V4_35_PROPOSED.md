# 521016-17 — bend-end slit shape and S reading (PROPOSED, pending DUYET)

**Branch proposal from user directive 2026-10-16 ("SỬA TẠO NHÁNH TRÊN REPO").** Not merged to main.

## FACT
- `060730/060732` (AL t2.5): flange 15/10 mm narrower than the web; web edge flush with the bend line, `S=0`. The earlier output had a bare straight slit `T+0.2=2.7`; the user confirmed the slit but required the **lead (vòi dẫn)** that follows the material (value by material).
- `060722` (SPCC t1.2): web strip beyond the legs is set back by DATA steps `+5.1` (upper) and `+1.6` (lower) from the outer sharps, so `S>0` -> NO slit. The earlier output wrongly added four `1.4` slits.

## ROOT_CAUSE
- `AI_RULE_GAP`: `BEND_EDGE_RELIEF_90` gave only a depth, no shape/lead, and did not name which two edges define `S`; the lead existed only for BOXMET corners.
- `AI_RULE_MISAPPLICATION`: `S=0` was assumed instead of reading the steps.

## LESSON
Read `S` between the bend-zone start line and the neighbouring web edge from source steps; `S>0` no slit; `S<=0` one connected Green `LINE + ARC R0.5 + LINE` with lead `LeadVal` (3.0 only for material exactly `SS` and t<6, else 6.0) on the void side away from the flange. Executable: `tools/slit_geometry.py`, `tests/test_bend_end_slit_lead.py`.

## Open for user decision
- `LeadVal` key for SPCC/SPHC/SECC (family SS) vs the literal exact-`SS` string.
- Lead side sign for non-rectangular junctions is only the BOXMET Case A pattern; other layouts need a proved transform.
